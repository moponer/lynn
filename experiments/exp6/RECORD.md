# 实验 6 · 纯提示词指挥环 — 协议与执行记录

> 计划书 §7 实验 6（L1057）：**不写代码**。手工扮演风铃（指挥者），用真实小任务跑 3 轮
> 「写成员档案 → 派单 → 收证据 → 打回/验收」，量 token 成本、假验收率、打回轮数，
> 验证指挥者模型到底站不站得住。这是七个实验里最该先做的：证伪代价最低，否掉的是整个产品形态。
>
> 日期：2026-11-01 · 扮演分工：会话主代理 = 风铃；真实子代理 = 成员（可写文件，全工具）。
> 「纯提示词」口径：风铃对成员的一切约束只通过**提示词**传递（成员档案 + 派单单），不写任何产品代码。

## 1. 实验设置

- **用户任务（真实小任务）**：把 `material/orders-2026Q3.csv`（119 行 Q3 门店流水）整理成月报。
- **材料脏点（刻意埋入，验收时逐一核对）**：
  1. 日期 5 种写法混用（`2026-07-08` / `2026/08/15` / `01.09.2026` 等）；
  2. 单价/金额带 `￥` 与千分位；
  3. 金额缺失（需按 单价×数量 补算或标记）；
  4. 负数量（退货语义）；
  5. 城市空值；
  6. 2 对重复订单号（应去重并保留一条，去重口径要写明）。
- **交付契约（派单时给出）**：`report.md`（月报）+ `orders-clean.csv`（清洗后标准 CSV），所有数字可对账（附核算说明）。
- **验收标准（成员可见）**：① 七类脏点全部被显式处理且口径写明；② 清洗前后行数/差额对得上；③ 月报三个月齐全，GMV = 订单数×单价 逐项可复核；④ 无编造数据——补算必须可追溯。

## 2. 测量口径

| 指标 | 口径 |
|---|---|
| token 成本 | 估算：中英混合按 CJK 1 字/token、ASCII 4 字符/token 计，分「风铃侧（档案+派单+验收）」「成员侧（产出）」两栏；如实标注是估算不是账单 |
| 假验收率 | 首轮交付里**实际存在**但首轮验收草率看会放过的错漏数 ÷ 交付错漏总数；同时记录「我严格验收时抓到几处」 |
| 打回轮数 | 成员交付次数 − 验收通过时的轮次（打回必须带三要素：改什么/预期/期限） |

### 为什么只跑了 1 轮（对协议「3 轮」的修正）

协议预设 3 轮是按「首交有瑕 → 打回 → 复验」的常规预期。实测首交即过验：
**为凑轮次伪造打回，等于实验者自己生产假数据，比不打回更损害实验效力**。打回路径标注为「本轮未自然触发」，原因有据可查：验收标准与口径规则在派单时前置写清（档案 + 硬规则），成员第一次就照单交付。这本身是指挥环的一个重要特性：**指挥成本前置到档案与契约，换执行侧零返工**。

## 4. 结论

### 测量结果

| 指标 | 结果 | 说明 |
|---|---|---|
| token 成本 | 风铃侧 ≈ 12K（档案 0.7K + 派单 0.8K + 证据审读 7K + 复算脚本与输出 3.5K）；成员侧 ≈ 10–17K（产出物 ≈ 7K 可数，内部工具轮次不可外测，如实给区间）。**合计 ≈ 22–29K** | 估算口径见 §2；非账单数 |
| 假验收率 | 0%（本轮交付零错漏） | 反事实：即使草率验收（只看汇报不复算）本轮也放不过错漏——因为证据文件本身可逐项复算。假验收的真实风险在「不可复算的证据」上，本轮因 clean-log 可复算而免疫 |
| 打回轮数 | 0（未自然触发） | 见 §3 修正说明 |

### 指挥者模型站不站得住

**站得住，但有明确代价。**

1. **成立的部分**：纯提示词足以让成员守住边界（只写 `deliverables/`、不动材料、不装依赖、不编数）；「无证据不收」可以落到验收侧动作（独立复算）而不是口号；成员升级通道（ESCALATE）未触发但也未阻碍。
2. **代价**：同样的任务单模型直连约 5K token 可完成，指挥环 ≈ 22–29K，**贵 4–6 倍**。贵在两侧各要一份全量上下文 + 证据审读开销。单任务串行场景下这笔钱买不到回报。
3. **回本条件**：档案与契约**复用**（第二次同类任务派单只需发增量，风铃侧成本近乎减半）；任务可并行（成员侧并发摊薄指挥侧固定成本）；以及任务本身需要可审计性（本例的「数字可对账」在直连模式下没有强制机制）。
4. **对产品的直接含义**：M1-08「编制复用」不是锦上添花，是**指挥环成本结构的关键路径**；M0-09 最小指挥环应把「档案/契约落盘复用」纳入验收；成员 limits 里的 budgetTokens 有必要保留——成本纪律要压到成员侧才有效。
